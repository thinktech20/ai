# Root Cause: Region Count Difference — Pipeline vs DS-Guru

**Document:** `fcb1511e-596a-4a56-b151-1e596afa569c`
**Date:** 2026-07-22

---

## Summary

| Source | Region count | GT (298464) | Gen (337X581) | Primary |
|---|---|---|---|---|
| DS-Guru local (Tao) | 2 | 1 | 1 | 337X581 / Generator |
| Old pipeline (pdfplumber) | 20 | 10 | 10 | 298464 / shared |
| Pipeline after pypdf2 switch | 22 | 11 | 11 | 298464 / shared |

Both the pipeline and DS-Guru use the same preprocessor code (`preprocessor_v2_final.py`).
The difference is in what `full_text` is fed **to** the preprocessor — not the preprocessor itself.

---

## Root Cause 1 — Heading marker injection (primary driver)

DS-Guru's `_extract_file_content_raw` (`ds-guru/app/main.py`, line 1646) calls
`_inject_pdf_heading_markers(page_text)` on every page before building `full_text`.

This function rewrites heading-like lines:

| Before injection | After injection |
|---|---|
| `1.2 Generator repairs` | `## 1.2 Generator repairs` |
| `5.3 Turbine inspection` | `## 5.3 Turbine inspection` |
| `GENERATOR` (ALL-CAPS) | `## GENERATOR` |

The preprocessor's sub-section patterns are:

```python
SUBSEC_GEN = r'(?m)^(\d{1,2}\.\d{1,2}(?:\.\d{1,2})?) Generator\b'
SUBSEC_GT  = r'(?m)^(\d{1,2}\.\d{1,2}(?:\.\d{1,2})?) (?:Turbine|Compressor|...)\b'
```

Once DS-Guru injects `## ` at the start of the line, `1.2 Generator...` becomes
`## 1.2 Generator...`. The regex anchored at `^` followed by `\d` no longer
matches — the line starts with `#`, not a digit.

**Effect:** All sub-section boundary detection is suppressed. Only the top-level
`HEADER` pattern survives, producing ~2 coarse regions (one GT block, one Generator
block) instead of 22 fine-grained sub-section regions.

---

## Root Cause 2 — Page separator (minor)

| | Page separator |
|---|---|
| DS-Guru | `text_content += page_text + "\n"` |
| Pipeline `parse_pypdf2` | `"\n\n".join(pages)` |

Single `\n` vs double `\n\n` between pages shifts char offsets slightly and can
affect regex matches that span page breaks, but this is not the main driver of
the region count difference.

---

## Root Cause 3 — Zero-length duplicate boundaries (secondary, pipeline-only)

In the new pipeline run, 6 of the 11 Gas Turbine regions are zero-length
(`start == end == 86494`). These are generated by `SUBSEC_GEN` logic: for each
generator sub-section that has the same next-GT-section offset, the same
`(end_pos, 'Gas Turbine', gt_esn)` tuple is appended multiple times.

After `boundaries.sort()`, consecutive identical tuples produce zero-length
regions, which inflate GT count from 5 → 11, creating a false 11/11 tie and
changing `primary_equip_type` from `Generator` → `shared`.

**Decision:** Not fixing this in the preprocessor — keeping Vince's code as-is
to maintain parity with the reference implementation.

---

## Decision: Align pipeline to DS-Guru extraction method

The pipeline's `parse_pypdf2` has been updated to match DS-Guru's
`_extract_file_content_raw` exactly:

1. **Added `_inject_pdf_heading_markers`** — same function as DS-Guru, applied per page
2. **Changed page separator** from `"\n\n"` (double newline) to `"\n"` (single newline),
   with char offsets updated from `+2` to `+1` accordingly

This is expected to produce ~2 coarse regions for this doc (matching DS-Guru)
 instead of 22 fine-grained regions.

### How to revert

In `pw_sdg_ai_ser_repo/silver/src/etl/fsr_v2/parsing.py`:

1. Remove the `_inject_pdf_heading_markers(page_text)` call:
   ```python
   # Remove this block:
   if page_text:
       page_text = _inject_pdf_heading_markers(page_text)
   ```
2. Change separator back:
   ```python
   # Revert: sum(len(p) + 1 ...) → sum(len(p) + 2 ...)
   start = sum(len(p) + 2 for p in pages)
   # Revert: "\n".join(pages) → "\n\n".join(pages)
   full_text = "\n\n".join(pages)
   ```
3. Optionally delete the `_inject_pdf_heading_markers` function above `parse_pypdf2`.

**Open question for team:** Confirm with Vince whether `_inject_pdf_heading_markers`
was an intentional design choice in DS-Guru or a general-purpose PDF ingest
artifact. If the 22-region granularity proves better for retrieval quality,
revert per the steps above.

---

## Remaining Gap: `primary_equip_type = shared` vs `Generator`

The zero-length duplicate boundaries (Root Cause 3) are the only reason the
pipeline shows `shared` instead of `Generator` for this doc. Without them:

- 5 GT regions (non-empty) vs 11 Generator regions
- Generator wins by both count and char coverage (158k vs 134k chars)
- `primary_equip_type = Generator` — matches DS-Guru primary direction

This is a known behavior, documented here, and not being patched in the preprocessor.
